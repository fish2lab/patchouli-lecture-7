# 方案：第 7 集 · 连 agent loop 都是插件（DeepSeek Harness 设计拆解 · 上）

> 依据：方案文档「DSH 讲解视频 · 第一期 SPEC」（2026-10-20）。下面的台词和画面以那份文档为准，事实按 2026-10-20 核对过的源码和网页改了几处（见文末「和 SPEC 不一样的地方」）。

## 一句话

让用过 Claude Code / Codex / pi、但没拆过 harness 内部的 B 站观众，在 8 分钟里记住：**DSH 唯一的结构性优势，是连 agent loop 都能在运行时被替换；这块地基来自 Koishi 的 Cordis。**

一句话论点：**给自己装插件，Claude Code、pi 都做得到；DSH 不一样的是连 agent loop 本身都是插件，装上拆下都干净——这块地基来自 Koishi 的 Cordis。**

## 受众和时长

- 受众：用过 Claude Code / Codex / pi 的 B 站观众，会一点 TypeScript 更好。
- 时长：约 8 分钟（系列惯例 4–5 分钟；SPEC「待定问题」已定按 8 分钟版做）。台词 74 条。
- 角色：八云蓝主讲（计算机题材，她自己就是「装在九尾狐身上的式神」，有一个梗），帕秋莉提问（懂行，追问细节）。
- 不讲：benchmark 分数、RL 数据、相位敏感（留给第二期）。

## 主线（观众带走的三件事）

1. harness 的扩展能力分三级：声明式 → 进程内中间件 → 可组合内核。
2. 第三级需要「可逆副作用 + 依赖响应」这套地基（Cordis 的时间、空间两个维度）。
3. 地基不等于进化算法：社区的进化循环把验证器放在可进化集合之外。

## 被否掉的方案

- 真录三家的屏幕：SPEC 定了「Demo 纯演示即可，不需要真实调用。可视化更重要」。三个窗口全部代码画，代码取自各家文档或照文档写的示意（示意的标「示意」）。
- 讲「动态插件重启就没」当作创造模式的特性：SPEC 写于旧版。0.2.1 里创造模式改成写文件 + `install_bundle` 持久安装，进程内动态定义已经不开放给模型。台词改成两种对照（见下）。
- 页与页之间翻书转场：这一集每段都用形状接形状（`noFlip`）。
- 深色「墨板」+ 3Blue1Brown 式配色、图框表和円相那一版：用户看过，觉得框线做作、布局乱、CS 不这么画 loop，改回第 1 集的纸面剪纸。
- 片名「会给自己装插件的 agent」：哪个 agent 都能给自己装插件（Claude Code 的 mod、pi 的 extension，第二页自己就讲了），不是 DSH 的特点。改成「连 agent loop 都是插件」，钩子最后几句也跟着改成「这一点别家也行，DSH 不一样的是 loop 本身也是插件」。
- 油库里语音（AquesTalk）：这一集改用小米 MiMo TTS（见下面「配音」）。

## 和 SPEC 不一样的地方

1. **创造模式不再在内存里挂插件**（DSH 0.2.1-rc.2）：模型先用只读工具查运行时，把插件写成工作区里的文件，经 `plugin_manager` 的 `install_bundle` 安装；要批准，装上后重启还在。SPEC 里「动态插件重启即失」只对进程内的动态定义（cordis-host-runner）成立，所以第 5 段的「重启」那一步改成两者对照。
2. **CC mods 的签名**是 `($, e, next)`，拒绝写 `return { deny: '…' }`。
3. **Koishi 4.7 的更新日志没写抽出 Cordis 的原因**，台词只说「4.7 把核心框架独立出来，取名 Cordis」，热重载要清副作用这句引生命周期文档。
4. 鸭哥文章里「上限相同」比较的是 DSH 和 Codex，不是 Claude Code；结尾改引「大多数开发者日常体验不会更好」那句。
5. 「今年 8 月开源」沿用 SPEC；DSH 仓库的提交从 2026-06-10 开始，公开日期在仓库里查不到。

## 配音（小米 MiMo TTS v2.5）

这一集不用油库里语音，改用小米 MiMo TTS v2.5（`tools/voice.mjs`，油库里版留在 `tools/voice-aquestalk.mjs`）。三款 TTS 模型现在限时免费，限流是每个模型每分钟 100 次，但并发很低，所以一句一句串行请求。key 只从环境变量 `MIMO_API_KEY` 读，不进仓库。

| 做法 | 为什么 | 依据 |
|---|---|---|
| 先用 `mimo-v2.5-tts-voicedesign` 按文字描述设计音色，挑一条存成 `tools/voices/<角色>.mp3`；正片每句都用 `mimo-v2.5-tts-voiceclone` 照这份样本念 | 文字描述每次出来都是一把新声音；用设计出的样本去克隆，八十句才像同一个人。克隆会照搬样本的气息和节奏，样本就是基准表演 | [官方使用指南](https://mimo.mi.com/docs/zh-CN/quick-start/usage-guide/audio/speech-synthesis-v2.5)；[官方 MiMo-Skills 的 TTS skill](https://github.com/XiaomiMiMo/MiMo-Skills/blob/main/skills/mimo-v2-5-tts/SKILL.md)；[小众软件论坛，2026-05-11](https://meta.appinn.net/t/topic/85202) |
| 语气写在 user 消息里（角色底色 + 这句的 mood），台词本身放 assistant 消息，不加「(风格)」标签 | 实测：clone 模型遇到台词开头的标签，后半句会念出不相干的字、时长翻倍；括号（() （） []）都会被当成标签 | 本集试验；官方指南「音频标签控制」 |
| 逐句生成，按 模型 + 样本 + 语气 + 文字 的哈希缓存在 `out/voice-cache/` | 模型每次结果不同；一次念一长段会跳字、提前结束。改一句只重抽这一句 | [V2EX](https://www.v2ex.com/t/1217169)；[mimo-tts-reeden](https://github.com/JINGZHE0635/mimo-tts-reeden) |
| 念不准的英文词在 `SAY` 表里换写法，只改送去合成的字，字幕不变：Koishi → こいし，ReAct → React，mod → Mod | 每个词换三四种写法各合成一遍，用本地 Whisper（large-v3-turbo）转写回来比对：Koishi 的拉丁写法全念不成 ko-i-shi，假名可以；ReAct 会念成两截；小写 mod 会念成 morn。turn、Plugin Manager、auto-evolve、reload 原样就对，转写出错的是那一条抽得不好，重抽 | 本集试验 |
| 后期变速：八云蓝 ×1.1、帕秋莉 ×1.05（ffmpeg atempo，不变调） | MiMo 念得比油库里慢，全片从 8 分半涨到 9 分 20 秒；变速控制在 1.1 以内听不出来 | [SmartSub 的 MiMo 说明，2026-09](https://smartsub.linxiaodong.com/guides/tts/xiaomi-mimo)（MiMo 没有语速参数） |
| 切首尾静音（阈值约 -38 dB，前留 60 ms、后留 150 ms），有声部分对齐到 -16 dB，峰值不超过 -1 dB；24 kHz、48 kbps MP3 | 句间停顿交给时间轴；短句不用一遍式 loudnorm；油库里那套 16 kHz / 32 kbps 会让齿音发闷 | [an issue #315，2026-10-02](https://github.com/thorwhalen/an/issues/315) |
| 片尾和发布文案写明「AI 合成，音色由文字描述生成，未使用任何真人或声优的声音」，投稿勾选 AI 合成声明 | 东方原作没有配音，角色「声优」都来自同人作品，不克隆、不模仿任何人；《人工智能生成合成内容标识办法》要求标识 | [标识办法](https://press.nppa.gov.cn/zcfg/202606/t20260609_993253.html) |
