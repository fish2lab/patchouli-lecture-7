| 台词 | 画面 |
|---|---|
| 蓝：想改一个 harness 的行为，有三级做法。 | loop 徽章飞到右上角候着；墨板上「啪」地立起三级台阶的轮廓 |
| 蓝：第一级，声明式扩展：skill、MCP、settings 里的 hook。 | 第一级点亮，写三个名字 |
| 蓝：它们只能给 harness 喂材料：多一段说明，多一个工具，多一个外部脚本。 | 三张小纸条（说明 / 工具 / 脚本）从外面喂进一个蓝色的 harness 方块，方块本身不变 |

| 蓝：第二级，进程内中间件：pi 的 extension，Claude Code 的 mod。 | 第二级点亮 |

## 3 Cordis（cordis，约 100 秒）· 满墨板

主物件：一棵插件树。插件身上贴着「符」（每一次注册，就是一张符）。

| 台词 | 画面 |
|---|---|
| 帕：连循环都能换……拔错一个，不就全乱了？ | 墨板长成满墨板，两人缩到下角；第三级台阶的框长成插件树的根，树一层层长出来（服务、插件） |
| 蓝：难点就在这儿：插件在进程里是有状态的。 | 镜头推近一个插件 `test-gate` |
| 蓝：它注册了工具，挂了监听器，还被别的插件依赖着。 | 它身上贴出三张符：`tools.register`、`on('tools/pre-execute')`、`effect`；另一个插件伸一根线依赖它 |
| 蓝：要是直接拔掉，这些注册还留在原地，就成了悬空引用。 | （假设）硬拔：插件被扯走，符还挂在空中，线头悬着，红色 |
| 帕：就像撤掉一个式神，贴出去的符也得一张张收回来？ | 倒回去（时间倒放的效果） |
| 蓝：正是。Cordis 管这叫可逆副作用：每一次注册，都附带一张撤销的符。 | 每张符背面翻出青色的「撤销」；右边贴真代码 `register()` 返回撤销函数（`vendor/cordis/src/events.ts`） |
| 蓝：插件卸载时，按相反的顺序，一张张揭掉。这是时间上的可组合。 | 底下一根时间轴，三张符按贴上的顺序排着；卸载时从最后一张往前一张张揭掉；标「时间」 |
| 蓝：第二件事，叫依赖响应。插件用 inject 写明自己要哪些服务。 | 另一个插件 `consumer` 身上挂着 `inject = ['greeter']`，一根线连到服务 `greeter` |
| 蓝：服务到齐才启动；服务一走，依赖它的插件先停下，等它回来再重新加载。 | `greeter` 消失 → `consumer` 变灰「等待」；`greeter` 回来 → `consumer` 重新亮起；标「空间」 |
| 蓝：这是空间上的可组合。Cordis 的论文，题目就叫时空可组合性的编程范式。 | 时间轴和依赖图拼成两根坐标轴「时间 × 空间」；论文题目英文小字 + arXiv 编号 |
| 帕：这套东西，是为 agent 发明的？ | — |
| 蓝：不是。它来自 Koishi：4.7 版把核心框架独立出来，取名 Cordis。 | 左边一棵小一点的树「Koishi」，同一个根 |
| 蓝：Koishi 的插件本来就要热重载，卸载时得清掉所有副作用。 | Koishi 树上一个插件卸下，符一张张揭掉（同一套动作） |
| 蓝：DSH 把 Cordis 的源码整个收进了自己的仓库。 | 根被复制一份，嵌进 DSH 树的底下，标 `vendor/cordis`；最后整棵树压扁成一块青色地基板「Cordis」，墨板缩回中墨板 |

交接 → 4：`dsHoSlab`（中墨板，底部一块青色地基板「Cordis」）。

## 5 同题三解（demo，约 105 秒）· 满墨板

主物件：三个窗口；后半段只剩 DSH 的事件链。代码都是代码画的「纯演示」，CC 和 pi 的写法照各自文档，DSH 插件是照 DSH 的接口写的示意。

| 台词 | 画面 |
|---|---|
| 蓝：来做个对比：同一个需求，三个 harness 各做一遍。 | 三根横条长成三个窗口，墨板变满 |
| 蓝：需求是：测试连续失败三次以后，拦下第四次，让 agent 先写下失败原因。 | 顶上一条需求卡：三个红叉 ✗✗✗，第四个被拦（红色手掌） |
| 蓝：Claude Code：让 Claude 写一个 mod，挂在工具调用事件上，数失败次数，第四次直接拒绝。 | 左窗口：`on('tool.call', …)` 逐字打出；底部「本会话热加载」 |
| 蓝：pi：写一个 extension，在工具调用时返回 block 和原因，放进目录，reload 一下。 | 中窗口：`pi.on("tool_call", …)` + `return { block: true, reason }`；底部 `/reload` |
| 蓝：DSH：agent 先查运行时，找到工具执行前的那个事件，再自己写插件、自己装上。 | 右窗口：先 `cordis_inspect_query` → 找到 `tools/pre-execute` → 写插件 → `install_bundle` |
| 帕：三家都做到了。那 DSH 的看点在哪？ | 三个窗口都亮一个绿勾 |
| 蓝：在出错以后。我们故意写错一个插件：漏掉一句 next。 | 左中两个窗口退下，DSH 窗口展开成一条事件链 `tools/pre-execute`：几个监听器方块 → 默认放行 → 执行；坏插件那一行 `return next()` 被划掉 |
| 蓝：链条断在这一层：后面的监听器和默认的放行全被吞掉，工具一个都跑不起来。 | 光点到坏插件就停住、堆积变红；后面的方块全暗 |
| 蓝：把它卸载。它注册的监听器和工具按相反的顺序撤销，其余工具恢复正常。 | 坏插件身上的符倒序揭掉（青色），链条重新接上，光点流过去 |
| 蓝：再重启一次。只活在内存里的动态定义，会被清空。 | 一道白闪；一个虚线的「动态定义」方块消散 |
| 蓝：经 Plugin Manager 装进配置的插件，重启以后还在。 | 一个实线的插件方块（写在 profile 里）在白闪之后仍在原位 |
| 蓝：最后把整棵插件树打印出来：agent loop，只是其中一行。 | 窗口里打出 `dsh --profile web --dump-config` 和一段 YAML（照 `packages/bundle/base/cordis.patch.yml`，示意），`- id: agent-loop` 那几行高亮 |

交接 → 6：高亮的 `agent-loop` 那一行（`dsHoRow`）。
